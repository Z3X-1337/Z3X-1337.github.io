03 / METHOD

Start with evidence. End with an explainable decision.

The same operating model appears across the public tooling: define the boundary, preserve context, make the signal explainable, test the artifact, and state what the evidence cannot prove.

01

Scope first

State the authorized use case, supported inputs, expected outputs, and explicit limits before expanding coverage.

02

Normalize evidence

Transform raw events into structures that can be counted, stored, filtered, correlated, tested, and exported without losing provenance.

03

Explain the signal

A detection should expose the observation, threshold, or rule that produced it rather than hiding the reasoning behind a severity label.

04

Test behavior

Parsing, CLI contracts, storage, package installation, edge cases, and supported Python versions are all part of the engineering surface.

05

Report uncertainty

Repeated failures can be user error. IOC patterns are not reputation verdicts. ATT&CK mappings are analyst assistance, not attribution.

06

Iterate from use

New features follow an analyst need or evidence gap. Reliability and interpretability come before superficial feature count.

DETECTION LOOP

Hypothesis → telemetry → evidence → decision.

01Form the hypothesis

What behavior would be suspicious, and under what context could the same signal be benign?

02Define required telemetry

Identify the source fields needed to test the hypothesis and preserve the original evidence form.

03Run deterministic analysis

Prefer reproducible rules and thresholds first; enrichment should never obscure the original observation.

04Document the decision boundary

Record evidence, confidence, limitations, and recommended next actions for human review.
