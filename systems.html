Method / evidence-first

Start with the system. End with an explainable decision.

Whether the task is a SOC workflow or an authorized web review, the useful result is a clear observation with enough context for another person to reproduce and challenge it.

Operating loop

The work moves from context to evidence — not from a checklist to a label.

This is a working discipline for public tooling and authorized security research, not a claim that every question has an automated answer.

01 / Scope

State the boundary.

Identify supported inputs, authorized use, limits, and the question the workflow is meant to answer.

02 / Understand

Model the system.

Map users, data, events, operations, resource ownership, and relevant trust boundaries before drawing conclusions.

03 / Observe

Collect stable evidence.

Normalize raw inputs into structures that can be counted, tested, traced, and reviewed.

04 / Explain

Show the reasoning.

Expose the policy, threshold, sequence, or data relationship that produced the observation.

05 / Validate

Challenge the result.

Use tests, known edge cases, controlled inputs, and independent review to check false-positive paths.

06 / Report

Keep the limits visible.

Separate what was observed from what was inferred, and describe the minimum next action needed for review.

Working stance: Signal is not certainty. A result should preserve the evidence that supports it and the uncertainty that remains.

Questions before code

The quality of a security workflow begins with the question it can honestly answer.

For an authentication event, that might be: “What events from this source crossed the configured threshold, and what evidence supports review?” For an HTTP response, it might be: “Which selected controls appeared on the final response after redirects?”

The intent is intentionally narrower than “Is this safe?” or “Is this malicious?” Broad labels can hide the conditions, coverage gaps, and human judgment that still matter.

observation → hypothesis → controlled test → result → interpretation → next question
